## 1. 背景与问题

- H&E 染色免疫细胞的人工判读费时、重复、依赖个人经验;巨噬细胞样本仅 1,624 张,与最多类(8,453 张)相差约 **5 倍**,类别不均衡是核心数据挑战。
- 产品定位:**辅助判读工具,而非替代病理医生**——模型给出识别结果与依据,不确定时明确交还人工。

## 2. 场景调研(公开资料桌面研究)

| 公开资料洞察 | 对本产品的设计输入 |
|---|---|
| 病理人力缺口持续扩大:美国 HRSA 预测到 2037 年全职病理医生缺口约 4,230 人;2024 年综述(Walsh et al.)记录了全球病理医生数量下降与工作量上升的双重压力 | 需求真实性确认:工具价值锚定"提升单次判读效率与一致性",而非替代诊断 |
| 监管已为 AI 病理放行:2021.09 美国 FDA 以 De Novo 路径授权 Paige Prostate——美国首个 AI 数字病理产品,范式为"辅助定位可疑区域 + 病理医生最终确认" | 产品边界依据:本工具"低置信(<50%)强制建议人工复核"的设计与该范式同构;指标上相应更关注召回率(漏检)而非仅准确率 |
| 可解释性是临床信任的关键,但"差的可解释"反而降低信任:Rosenbacke et al.(2024, PMC)显示 XAI 仅在解释清晰、简洁、临床相关时提升医生信任;Evans et al.(2022)提出数字病理"可解释性悖论" | Grad-CAM 配备颜色标尺与「如何解读热力图」说明,并明确标注"颜色为相对影响而非概率"——避免过度解释带来的误导 |
| 数字病理 / 远程阅片被视为应对人力短缺的最重要手段(Labcorp 2026 调研:59% 病理医生持此观点) | 场景确认:单图快速判读 + 结果可复核的交互式工具是合理切入点 |

来源:Rosenbacke et al. 2024([PMC11561425](https://pmc.ncbi.nlm.nih.gov/articles/PMC11561425));Evans et al. 2022 [The Explainability Paradox](https://www.sciencedirect.com/science/article/pii/S0167739X22000838);Stevens et al. 2023 [TrAAIT 量表](https://pubmed.ncbi.nlm.nih.gov/37981107);[PathAI 数字病理与人力研究](https://www.pathai.com/blog/from-pixels-to-precision-005-the-role-of-digital-pathology-in-addressing-pathology-workforce-challenges);FDA De Novo 授权公告(2021.09,Paige Prostate)。

## 3. 目标与非目标

- **目标**:3 类细胞(B 细胞 / T 细胞 / 巨噬细胞)的单张图像快速辅助识别;输出置信度与概率分布;低置信时强制提示人工复核;提供可解释依据(Grad-CAM)。
- **非目标**:临床诊断结论、全自动批量判读(列入后续迭代)、多中心数据泛化验证。

## 4. 用户与场景

病理 / 生物学研究人员,在实验或教学场景中对单张 H&E 图像做快速判读与复核。

**用户故事(节选)**:
- 作为病理研究人员,我想上传单张 H&E 图像并立即看到预测类别与置信度,以便快速判断是否需要人工复核;
- 作为团队负责人,我想在界面常驻看到各模型性能对比,以便带着明确预期使用工具;
- 作为非技术使用者,我想看到模型"关注哪里"的归因(热力图)与"什么时候不可信"(低置信预警),以便信任或质疑结果。

## 5. 需求与优先级

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 | 图像上传与识别 | PNG/JPG 单图上传,5 种模型可选(ResNet50 / DenseNet121 / EfficientNet-B0 / ViT-B/16 / MobileNetV3) |
| P0 | 置信度与概率分布展示 | 预测类别 + 置信度分数 + 三类概率条形图 |
| P0 | 低置信预警 | 置信度 < 50% 时显示"建议人工复核"警告(人机协同边界) |
| P1 | 集成模式 | 默认 MobileNetV3 + EfficientNet-B0 软投票;支持全部 10 个两两集成组合 |
| P1 | Grad-CAM 可解释 | 逐集成组件生成热力图并叠加原图,附颜色标尺 |
| P2 | 批量上传 / 结果导出 | 后续迭代 |

## 6. 系统架构、主链路与界面原型

五层架构(见 `系统架构图.png`):交互层(Streamlit)→ 推理编排层(预处理 → checkpoint 加载 → 推理 → soft voting → 置信度判断)→ 模型层(5 架构)→ 可解释层(Grad-CAM,并行支路)→ 资产层(权重 / 数据 / 报告)。

主链路(见 `判读主链路泳道图.png`):上传 → 预处理(224×224 + 归一化)→ 模型推理(单模型 / 集成 soft voting)→ 结果渲染 → 置信度判断:≥ 50% 正常展示;**< 50% 触发"建议人工复核"预警**。Grad-CAM 热力图与主链路并行生成,汇入结果页。

界面原型(见 `界面原型线框图.png`):Frame A 上传态(侧边栏模型选择与性能表常驻 + 上传区)+ Frame B 低置信结果态(原图 / 结果卡 / 红色预警条 / Grad-CAM 对照),含三条交互设计决策标注;真实交付截图见 `app_ui_home.png`。

## 7. 评测与验收标准

- 统一固定测试集;指标:**逐类召回率与宏平均 F1 为主**(准确率仅作参考,避免被多数类主导)、ROC-AUC / LogLoss 为辅,配合混淆矩阵做错判归因。
- 模型选型规则:集成方案必须在宏 F1 上优于最优单模型,且错误相关性足够低(互补)。
- 交付验收:端到端应用可运行、5 个模型 checkpoint 全部可加载、报告评测图表可从 checkpoint 一键复现。

## 8. 关键决策记录(ADR)

1. **集成 vs 单模型**:10 个集成组合全量评测,MobileNetV3 + EfficientNet-B0 软投票宏 F1 0.488 vs 最优单模型 0.455(相对 +7.3%),错误相关性 0.388(互补性强)→ 采用集成。代价:准确率 62.1% → 61.2% 微降,换取类别均衡表现——辅助判读场景更关注逐类召回而非被多数类撑高的准确率。
2. **主指标 = 逐类召回率 + 宏 F1**:5:1 类别不均衡下,准确率是"虚荣指标";召回率直接暴露少数类漏检,混淆矩阵定位错判方向,作为 badcase 归因与迭代依据。
3. **低置信阈值 = 50%**:产品层面定义"模型不确定"的边界,低于阈值不隐藏结果、但强制附加人工复核建议——把最终决定权留给人。
4. **4 类 → 3 类**:CD4+ 与 CD8+ T 细胞按业务口径合并为 T 细胞,与判读使用场景一致。

## 11. 痛点 → 方案 → 结果

| 痛点 | 方案 | 结果 |
|---|---|---|
| 病理人力缺口,重复判读耗时、依赖经验 | 单图自动判读:上传 → 预处理 → 集成推理,秒级返回 | 端到端工具可交互交付,CPU 即可运行 |
| 类别不均衡导致少数类(Macrophage)漏检被准确率掩盖 | 逐类召回率 + 宏 F1 为主指标;加权采样与数据增强 | 宏 F1 相对 +7.3%(0.455→0.488),类别表现更均衡 |
| 模型黑盒,临床使用存在信任门槛 | Grad-CAM 归因 + 防误读标注 + 50% 低置信转人工 | 可解释交付,人机协同边界明确 |

## 12. 质量运营与实验设计(上线后规划,未执行)

- **质量运营口径**:本项目无线上用户,故无传统埋点 / AB 测试;AI 产品的质量运营等价物 = 统一评测集(回归测试)+ 混淆矩阵 badcase 归因(问题定位)+ 迭代清单(跟踪闭环)。
- **上线后 AB 测试设计**:双盲阅片对照——同一批 H&E 图像随机分流至"AI 辅助组"与"纯人工组",比较判读耗时、与金标一致率、低置信图像的人工复核触发率;按实验室 / 科室维度灰度放量。
- **埋点设计(若上线)**:低置信预警触发率、人工采纳率、逐模型使用占比——均为产品迭代输入。

## 14. 局限与生产化路径(Limitations & Path to Production)

**定级**:本项目为方法论完整的 PoC(概念验证原型)——验证的是评测协议、人机协同边界与可解释性设计,**尚未验证临床价值**;介于 toy demo 与企业级生产之间,未达到试点(Pilot)标准。

**当前主要局限**:
- 输入为课程裁剪的 100×100 单细胞小图;真实病理工作流为千兆像素 WSI 整张切片(先检测/分割、后分类),任务形态存在量级差异;
- 纯 H&E 形态学做免疫分型偏研究性——临床确认通常以免疫组化(IHC)标志物为准;
- 单中心数据;softmax 概率未经校准,50% 置信阈值为产品定义而非校准推导。

**生产化差距(五层)**:

| 层 | 要解决的问题 | 关键内容 |
|---|---|---|
| 性能与临床有效性 | 模型够不够好 | 多中心 / 多扫描仪 / 多染色批次数据扩展;任务形态升级(WSI → 检测 → 分类);指标与临床场景绑定(如辅助筛查的敏感度下限);概率校准(校准曲线 + 漏诊/误诊代价函数重定阈值) |
| 数据治理与合规 | 数据能不能用 | 医疗数据合规(人遗条例 / 个保法 / HIPAA)、脱敏与知情同意;标注委员会与标注一致性(多医生标注计算 kappa);SaMD 监管路径(NMPA / FDA 510(k) / De Novo)与 IEC 62304 软件生命周期 |
| MLOps 工程 | 服务稳不稳、迭代可不可控 | Streamlit 原型 → 容器化 API(并发 / GPU / 延迟 SLA);数据与模型版本化;评测集回归纳入 CI;数据漂移监控 + badcase 回流标注闭环 |
| 产品与工作流集成 | 用户真的会用吗 | 对接 LIS / PACS、支持批量;灰度上线与用户培训;误判责任划分;本地化 / 私有化部署(医院场景 SaaS 模式基本不适用) |
| 组织与流程 | 谁为它负责 | 跨职能团队(病理专家 / 法规 / QA)、模型变更控制委员会、发布与回滚策略 |

**PM 优先动作(若投入资源,6–12 个月)**:
1. 定义使用场景与验收指标——辅助筛查、教学、科研的指标口径完全不同,这是第一决策;
2. 多中心数据扩展 + 概率校准研究,基于代价函数重新确定置信阈值;
3. 搭建最小 MLOps 闭环:评测集回归纳入 CI、漂移监控、badcase 回流标注。
